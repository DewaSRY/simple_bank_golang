# Simple Bank — Dashboard & Transaction PRD

## 1. Product Overview

**Simple Bank** is a personal banking application that allows users to manage multiple bank accounts and perform basic financial transactions.

The dashboard provides users with an overview of their accounts and transaction history.

Users can:

- View their bank accounts and balances
- Create additional accounts
- Delete accounts
- Deposit money into an account
- Transfer money between accounts
- View and filter transaction history

The application uses **IDR (Indonesian Rupiah)** as its only supported currency in the initial version.

---

# 2. Dashboard

The dashboard is the main page displayed after a user successfully logs in.

It consists of two primary sections:

1. **Account Overview**
2. **Transaction History**

---

## 2.1 Account Overview

The Account Overview displays all accounts belonging to the authenticated user.

Each account displays:

- **Account Name**
- **Account Number**
- **Current Balance**
- **Description**, if provided

### Account Number

The account number:

- Is automatically generated by the system.
- Must be unique.
- Must be stored and treated as a **string**.
- Must not be editable by the user.

Example:

```text
Account Name: Main Account
Account Number: 100000123456
Balance: Rp 5,000,000
Description: Primary bank account
```

---

# 3. Main Account

When a user registers for the first time, the system automatically creates a **Main Account**.

The Main Account:

- Is created automatically during registration.
- Is owned by the user.
- Cannot be deleted.
- Acts as the default account for the user.
- Receives the remaining balance when another account is deleted.

The user does not need to manually create the Main Account.

---

# 4. Create Account

Users can create additional accounts from the dashboard.

### Required Fields

| Field       | Required | Description          |
| ----------- | -------- | -------------------- |
| Name        | Yes      | Name of the account  |
| Description | No       | Optional description |

The account number is automatically generated by the system.

### Example

```text
Name: Savings
Description: Money reserved for future expenses
```

After successful creation, the new account should immediately appear in the user's Account Overview.

---

# 5. Delete Account

Users can delete accounts that they have created.

The **Main Account cannot be deleted**.

### Account Deletion Behavior

If the account being deleted has a balance greater than zero:

1. The system transfers the entire remaining balance to the user's Main Account.
2. The transfer is recorded as a transaction.
3. The selected account is deleted.

If the account has a zero balance:

1. No balance transfer is required.
2. The account is deleted.

### Important

Account deletion and balance transfer must be performed as a **single database transaction**.

If any part of the operation fails, the entire operation must be rolled back.

---

# 6. Transaction

Users can perform financial transactions from an account.

Before performing a transaction, the user must select the account that will be used.

### Transaction Flow

```text
Select Account
      ↓
Select Transaction Type
      ↓
Enter Transaction Details
      ↓
Confirm Transaction
      ↓
Transaction Completed
```

The initial version supports two transaction types:

- **Deposit**
- **Transfer**

---

# 7. Deposit

A deposit adds money to the selected account.

### Deposit Flow

1. User selects an account.
2. User selects **Deposit**.
3. User enters the deposit amount.
4. User enters an optional description.
5. User confirms the transaction.
6. The system increases the account balance.
7. The system creates a transaction record.

### Deposit Fields

| Field       | Required | Description                      |
| ----------- | -------- | -------------------------------- |
| Amount      | Yes      | Amount of money to deposit       |
| Currency    | Yes      | Fixed to IDR                     |
| Description | No       | Optional transaction description |

### Example

```text
Account: Main Account

Transaction Type: Deposit
Amount: Rp 1,000,000
Currency: IDR
Description: Monthly salary
```

After a successful deposit:

```text
Previous Balance: Rp 5,000,000
Deposit:          Rp 1,000,000
New Balance:      Rp 6,000,000
```

---

# 8. Transfer

A transfer moves money from the selected source account to another account.

The destination account can belong to:

- The same user
- Another user registered in Simple Bank

### Transfer Flow

1. User selects the source account.
2. User selects **Transfer**.
3. User selects or searches for the destination account.
4. User enters the transfer amount.
5. User optionally enters a description.
6. User reviews the transfer.
7. User confirms the transaction.
8. The system transfers the money.
9. The system records the transaction.

---

# 9. Selecting a Destination Account

When performing a transfer, the system should make it easy for users to select the destination account.

The UI should initially display **recently used destination accounts**.

The user can also search for an account using its account number.

### Account Search

Users can:

- Select an account from their recent accounts.
- Search for an account by account number.

Example:

```text
Transfer To

Recent Accounts
────────────────────────────
John's Account
Account: 100000123456

Savings Account
Account: 100000987654

Search Account Number
[ 100000123456              ]
```

The system should only allow transfers to valid accounts.

---

# 10. Transfer Fields

| Field               | Required | Description                               |
| ------------------- | -------- | ----------------------------------------- |
| Source Account      | Yes      | Account from which money will be deducted |
| Destination Account | Yes      | Account receiving the money               |
| Amount              | Yes      | Amount to transfer                        |
| Currency            | Yes      | Fixed to IDR                              |
| Description         | No       | Optional transfer description             |

### Example

```text
From:
Main Account
100000123456

To:
Savings Account
100000987654

Amount:
Rp 500,000

Description:
Monthly savings
```

---

# 11. Transfer Validation

Before completing a transfer, the system must validate:

- Source account exists.
- Destination account exists.
- Source and destination accounts are valid.
- Transfer amount is greater than zero.
- Source account has sufficient balance.
- Currency is IDR.
- User is authorized to transfer from the source account.

The system must prevent:

```text
Transfer Amount > Source Account Balance
```

---

# 12. Transaction Atomicity

Transfers must be executed atomically.

A transfer consists of:

```text
Source Account
      ↓
   Deduct Money
      ↓
Destination Account
      ↓
   Add Money
      ↓
Create Transaction Records
```

All operations must succeed together.

If any operation fails:

```text
ROLLBACK
```

The source balance, destination balance, and transaction records must remain unchanged.

---

# 13. Transaction History

The dashboard displays transaction history for the user's accounts.

Each transaction should contain:

- Transaction Date
- Transaction Type
- Amount
- Currency
- Description
- Source Account, when applicable
- Destination Account, when applicable

### Transaction Types

The initial version supports:

- **Deposit**
- **Transfer In**
- **Transfer Out**

For example:

| Date         | Type         |        Amount | Currency | Description       |
| ------------ | ------------ | ------------: | -------- | ----------------- |
| Aug 31, 2026 | Deposit      | +Rp 1,000,000 | IDR      | Salary            |
| Aug 30, 2026 | Transfer Out |   -Rp 500,000 | IDR      | Savings           |
| Aug 30, 2026 | Transfer In  |   +Rp 500,000 | IDR      | From Main Account |

---

# 14. Transaction Filtering

Transaction history can be filtered by **month**.

The user can select a month and view transactions that occurred during that month.

Example:

```text
Transaction History

[ August 2026 ▼ ]

Aug 31    Deposit          +Rp 1,000,000
Aug 30    Transfer Out     -Rp 500,000
Aug 28    Transfer In      +Rp 250,000
```

The default filter should be the **current month**.

---

# 15. Balance Rules

The system must maintain the following balance rules:

### Deposit

```text
New Balance = Current Balance + Deposit Amount
```

### Transfer Out

```text
Source New Balance = Source Balance - Transfer Amount
```

### Transfer In

```text
Destination New Balance = Destination Balance + Transfer Amount
```

Balances must never become negative.

---

# 16. Transaction Records

Every financial operation must create an appropriate transaction record.

### Deposit

Creates:

```text
Deposit
```

### Transfer

Creates two transaction records:

```text
Transfer Out
Transfer In
```

This allows each account to maintain its own transaction history.

---

# 17. Currency

The initial version of Simple Bank supports only:

```text
IDR — Indonesian Rupiah
```

Currency selection should therefore be **disabled/read-only** in the UI.

Future versions may support multiple currencies.

---

# 18. Error Handling

The application should provide clear error messages.

Examples:

### Insufficient Balance

> Insufficient balance to complete this transfer.

### Account Not Found

> The destination account could not be found.

### Invalid Amount

> Amount must be greater than zero.

### Transaction Failed

> We couldn't complete the transaction. Please try again.

### Account Deletion Failed

> We couldn't delete this account. Please try again.

---

# 19. Security & Authorization

Users must only be able to access their own accounts and transaction history.

The backend must enforce authorization for:

- Viewing accounts
- Creating accounts
- Deleting accounts
- Depositing money
- Transferring money
- Viewing transactions

The frontend must not be considered a security boundary.

A user must not be able to manipulate another user's account by modifying an account ID or account number in an API request.

---

# 20. Initial Scope

### Included

- User authentication
- Automatic Main Account creation
- Account overview
- Create account
- Delete account
- Automatic balance transfer during account deletion
- Deposit
- Transfer
- Account number generation
- Transaction history
- Monthly transaction filtering
- IDR currency

### Out of Scope

The following features are not included in the initial version:

- Multiple currencies
- Withdrawal
- Scheduled transfers
- Recurring payments
- Bank-to-bank external transfers
- Transaction export
- Transaction reversal
- Credit cards
- Loans
- Interest calculation
- Notifications
- Investment products

# 21. Core Acceptance Criteria

## Account

- [ ] A Main Account is automatically created when a user registers.
- [ ] Main Account cannot be deleted.
- [ ] Users can create additional accounts.
- [ ] Account name is required.
- [ ] Account description is optional.
- [ ] Account numbers are automatically generated.
- [ ] Account numbers are unique.
- [ ] Account numbers are stored as strings.
- [ ] Users can delete their own accounts.
- [ ] Remaining balance is transferred to Main Account before deletion.
- [ ] Account deletion and balance transfer are atomic.

## Deposit

- [ ] User must select an account before depositing.
- [ ] Deposit amount is required.
- [ ] Deposit amount must be greater than zero.
- [ ] Currency is fixed to IDR.
- [ ] Description is optional.
- [ ] Account balance increases after a successful deposit.
- [ ] A deposit transaction is created.
- [ ] Failed deposits do not modify the account balance.

## Transfer

- [ ] User must select a source account.
- [ ] User must select a destination account.
- [ ] Destination accounts can be selected from recent accounts.
- [ ] Destination accounts can be searched by account number.
- [ ] Transfer amount is required.
- [ ] Transfer amount must be greater than zero.
- [ ] Source account must have sufficient balance.
- [ ] Currency is fixed to IDR.
- [ ] Transfer creates a Transfer Out transaction.
- [ ] Transfer creates a Transfer In transaction.
- [ ] Source and destination balances are updated atomically.
- [ ] Failed transfers do not modify either account.

## Transaction History

- [ ] Users can view their transaction history.
- [ ] Transactions display transaction date.
- [ ] Transactions display transaction type.
- [ ] Transactions display amount.
- [ ] Transactions display currency.
- [ ] Transactions display description when available.
- [ ] Users can filter transactions by month.
- [ ] Current month is selected by default.
- [ ] Users cannot view transactions belonging to another user.
